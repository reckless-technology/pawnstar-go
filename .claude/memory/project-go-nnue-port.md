Goal (decided 2026-06-30): incorporate the C++ improvements made to `../pawnstar` since the Go port forked (2026-05-11) into `pawnstar-go`. User chose **NNUE first**, with a **self-play SPRT harness** to gate changes, using Go's `simd/archsimd` for kernels (see [[reference-go-simd-archsimd]]), and the Go evaluator must **load the pawnstar `*.bin` net directly**.

**C++ NNUE architecture (v12, the shipped default) — the port target:**
- Features: Chess768 (768 = 2 colors × 6 types × 64 squares) per perspective, × **8 king buckets** (selected by king file-pair × board-half; `kKingBucketMap`), bucket-major → `kFeatureRows = 6144`.
- FT/accumulator: **1024 int16** per perspective; two perspectives concatenated [stm | ntm].
- Activation: **SCReLU** (clamp to [0, QA=255] then square), NOT plain clipped ReLU.
- Output: 2×1024 int16 weights (scale QB=64) → 1 scalar; dequant tail reduces one QA, adds bias, ×`kScale=400`/(QA·QB), clamps to ±kMaxEvaluation.
- Two forward passes in `src/nnue.h`: `EvaluateExact` (int16, the reference/trainer-matching path) and `Evaluate` (int8 fast path, bit-identical because `kInt8Shift=9` avoids maddubs saturation).
- Net file: 32-byte `NetHeader` (magic "PSN1", format_version=1, then input_size/king_buckets/hidden_size/qa/qb/scale) + int16 arrays (feature_weights col-major `feature*hidden+i`, feature_bias, output_weights). `pawnstar-v12.bin` payload = 12,589,152 B. Native little-endian int16 ⇒ direct read on amd64.
- Accumulator maintained incrementally across make/undo, **lazy/deferred** (brought current only when an eval reads it, on eval-cache miss) — the C++ lazy update was +20.66 Elo. Refresh only on king-bucket crossing. 8 MB lockless eval cache (zobrist→score); C++ found 8 MB optimal (32 MB was −7 Elo).

**Correctness gates (mirror C++):** Go `EvaluateExact` == C++ 250-FEN reference at **0 cp**; incremental == full-refresh bit-identical; then SPRT vs the HCE baseline. BK accepted-move sets are eval-specific — regenerate after switching to NNUE.

**After NNUE, the portable search wins to port (SPRT-gated, one at a time, margins tuned for THIS engine — C++ found the whole stack together regressed −174 Elo):** reverse futility pruning (C++ +114.8), quiescence SEE pruning (+38.6), internal iterative reduction (+31.8), late-move pruning (+18.6), countermove + 1-ply continuation history (+9). Plus robustness: 50-move eval scaling toward draw, finer time-deadline polling (C++ 64k→2k nodes) + Move Overhead, illegal-PV fix. **Skip** (C++ tested & rejected): aspiration re-tune, make/unmake, correction history, singular extensions, output buckets, NNUE hidden layer, asm kernels, null-move R=3. Go already has: magic bitboards, YBW parallel, copy-make.

**Validation infra:** fastchess is installed (used by C++ `tools/run_sprt.sh`). Build an SPRT harness for `pawnstar-go(candidate)` vs `pawnstar-go(baseline)`; the current HCE build is baseline #0. SPRT runs are long (thousands of games) — run in background.

- **Search-infra rework (user-directed, post-NNUE, on `main`):**
  - **Lockless TT DONE (commit 8055e54).** Hyatt XOR trick mirroring C++ `transposition_table.h`/`move.h`: TT metadata packed into the move's spare bits (bits 23–24 nodeType, 25–32 depth int8, 33–40 age, 41–63 score signed-23bit shared as sort key + stored score); identity stays bits 0–21. Cell = two `atomic.Uint64` (`key=hash^data`, `data`=packed move); `find` accepts iff `key^data==hash` (torn pair → benign miss, also the collision guard). `searchCancelledScore` (−12345678) is a pure sentinel, never recorded. move.go has `withTTData`/`setTTAge`/`ttDepth/ttNodeType/ttAge`/`bits`/`moveFromBits`.
  - **YBW parallel search REMOVED (commit 983b528, branch `remove-ybw`, unmerged).** Search now single-threaded (one goroutine via startThinking for UCI stop; sequential move loop). Deleted runWorker/searchMovesParallel/newWorkerState/canGoParallel/wasCutoff/parallelSlots/maxNumGoRoutines/parallel debug counters + forceSerialSearch test helper (search is inherently serial+deterministic now; bkCases unchanged & still 24/24). `git merge --ff-only remove-ybw` to land it.
  - **Pruning/reduction stack PORTED (commit 9b3a0f2, on `main`).** Copied the verified C++ techniques from `search_state.h` (margins carry over — NNUE eval is same cp scale): internal iterative reduction (`noTTReduceMinDepth=4`), reverse futility pruning (`rfpMaxDepth=7`, `rfpMargin=80`), null-move retuned to gate on `staticEval>=beta` (was pstScore>beta+100), late-move pruning (`lmpMaxDepth=8`, `lmpBase=3`, idx>=base+depth²), LMR retuned to C++ thresholds (idx>3/-1, idx>6&depth>3/-2, zero-history/-3, any move type), qsearch SEE pruning (stop at first losing capture). Also: captures now score by **pure SEE** (moved history/PST into the quiet branch in `scoreAndSortMovesInner`) so move-score sign == SEE sign, which qsearch SEE pruning needs. Cut EBF ~4.1→~2.5. **SPRT vs pre-pruning baseline: H1 accepted, +183 Elo @10+0.1 (also +224 @5+0.05).** BK sets regenerated (pruning changes fixed-depth moves). Did NOT port the check EXTENSION or countermove/continuation-history move-ordering (separate, still available in C++ `search_state.h`). Baseline binary `pawnstar-go-preprune` (gitignored).
  - **Check extension + countermove + continuation history DONE (commit 8e81a53, on `main`).** Added the check extension (in-check node → depth++ at top of searchAlphaBeta). **Rewrote move ordering to the C++ banded ScoreAndSortMoves** (winningCaptureBase=1<<20 + SEE; killers 1<<19+1/1<<19; countermove 1<<19−1; quiets min(history+contHist, 1<<19−2); losing captures = negative SEE) — **dropped the Go enemy-attack penalty + PST-delta terms** and `scoreAndSortMovesInner`/`pieceVals`. Threaded `prevMove` through searchAlphaBeta/searchSingleMove (moveNone at root/null/qsearch). New per-searchState `countermoves [contKeys]move` + `continuationHistory []int16` (contKeys=7*64=448; key = piece*64+to = `move.pieceTo()`), persist across a search; `recordGood(ply,prev,m,isCutoff)` credits history+contHist always and killers+countermove for quiet cutoffs. Killers now track all isQuiet (was nonCapture-only). **SPRT +159.7 Elo @10+0.1 (H1 accepted, 123W/25L/80D)** vs the post-pruning baseline — large because it also fixed a pruning/ordering mismatch (LMP/LMR were tuned for the C++ ordering). BK regenerated. Did NOT port: 50-move eval scaling, finer deadline polling 64k→2k, illegal-PV fix d376b8a.
  - **Lockless eval cache DONE (commit 9b294d1, on `main`).** Ported C++ `EvalCache`: `evalHashEntry` is one `atomic.Uint64` = (hash & 0xFFFF...0000) | uint16(int16(score)); `find` accepts iff top-48-bits match (else hashNotFoundScore); `record` clamps ±30000 (int16 guard; mate scores never cached); `clear()` on evaluator change (EnableNNUE/LoadNNUEFile/UseNNUE toggle). Sized 1<<20 entries ≈ 8MB (C++ optimal). **Behavior-neutral single-threaded** (identical depth-13 node counts & PV), ~15% faster from higher hit rate; no SPRT needed. Removed the per-entry CAS spinlock.
